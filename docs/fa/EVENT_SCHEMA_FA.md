# شِمای رخداد — نسخه ۱ (Event Schema v1)

شِمای رخداد، قرارداد دادهٔ ورودی همهٔ اجزای StreamGuard است (دریافت، اعتبارسنجی، قوانین،
همبستگی و تحلیل). اعتبارسنجی **سخت‌گیرانه** است: هر تخطی ثبت می‌شود و هیچ رخدادی بی‌سرو
صدور دور ریخته نمی‌شود.

نسخهٔ انگلیسی: [README.md](../../README.md) §Event schema — مطالعهٔ مرتبط:
[API_FA.md](API_FA.md) و [ARCHITECTURE_FA.md](ARCHITECTURE_FA.md).

## فیلدها

نام فیلدها عیناً انگلیسی می‌ماند (این همان چیزی است که در JSON می‌فرستید):

| فیلد | الزامی؟ | نوع/قید | توضیح |
|---|---|---|---|
| `event_id` | بله | UUID v4 | کلید توان‌نمایی؛ تکرارش دوباره ذخیره نمی‌شود |
| `schema_version` | بله | باید `1` باشد | نسخهٔ شِما؛ هر مقدار دیگر رد می‌شود |
| `event_time` | بله | ISO 8601 UTC | زمان واقعی وقوع رخداد (نه زمان دریافت) |
| `source_id` | بله | `^[a-zA-Z0-9._-]{1,64}$` | شناسهٔ منبع فرستنده |
| `source_type` | بله | enum | نوع منبع |
| `severity` | بله | enum | شدت |
| `category` | بله | enum | دستهٔ رویدادی |
| `message` | بله | ۱..۵۱۲ نویسه | پیام نرمال‌شده |
| `attributes` | خیر | شیء JSON، ≤ ۴ KB (stringified) | دادهٔ دلخواه؛ بدون مقادیر محرمانه |
| `correlation_id` | خیر | ≤ ۱۲۸ نویسه | شناسهٔ همبستگی اختیاری |
| `trace_id` | خیر | ≤ ۱۲۸ نویسه | شناسهٔ ردگیری اختیاری |
| `actor` | خیر | ≤ ۱۲۸ نویسه | کاربر/سرویسِ انجام‌دهندهٔ عمل |

## فیلدهایی که سرور اضافه می‌کند

این فیلدها از سمت کلاینت قابل ارسال نیستند و توسط سامانه تنظیم می‌شوند:

| فیلد | معنا |
|---|---|
| `ingest_time` | زمان دریافت در سرور |
| `status` | `VALIDATED` یا `REJECTED` یا `PROCESSED` |
| `origin` | `synthetic` یا `external` — نشانگر خاستگاه داده |
| `rejection_reason` | دلیل رد (برای رخدادهای ردشده) |

## مقادیر مجاز enum

| فیلد | مقادیر مجاز |
|---|---|
| `source_type` | `app` · `infra` · `system` · `security` · `synthetic` |
| `severity` | `info` · `low` · `medium` · `high` · `critical` |
| `category` | `auth` · `network` · `application` · `data` · `system` · `config` · `security` |

## قواعد اعتبارسنجی

- `schema_version` باید دقیقاً ۱ باشد.
- `event_time` باید ISO 8601 UTC معتبر باشد (بند پایین) و **اختلاف آیندهٔ بیش از ۱۰ دقیقه
  مجاز نیست** (skew).
- `source_id` باید با الگوی `^[a-zA-Z0-9._-]{1,64}$` مطابق باشد.
- `message` باید ۱ تا ۵۱۲ نویسه باشد؛ در پارسر C++ طول بر حسب نویسهٔ UTF-8 شمرده می‌شود.
- `attributes` بعد از تبدیل به رشته حداکثر ۴ کیلوبایت؛ فیلدهای ناشناسِ سطح‌بالا در JSON
  رد می‌شوند و کلیدهای تکراری هم رد می‌شوند.
- هر تخطی → ثبت `ValidationFailure` (دلیل + نمونهٔ بریده‌شده ≤ ۲۵۶ بایت) و شمارش در
  پاسخ؛ رخداد هرگز بی‌سرو صدا حذف نمی‌شود.

## توان‌نمایی (idempotency)

`event_id` تکراری با موفقیت پذیرفته می‌شود (`duplicates` در پاسخ) اما دوباره ذخیره نمی‌شود
و تشخیص‌ها برایش دوباره اجرا نمی‌شود. در PostgreSQL درج با `ON CONFLICT (event_id) DO
NOTHING` توان‌نما است. این رفتار برای فرستنده‌هایی که retry می‌کنند، امن است.

## محدودیت‌ها

| قید | مقدار |
|---|---|
| بیشینهٔ اندازهٔ یک رخداد | ۴ KB |
| بیشینهٔ تعداد رخداد در هر batch | ۱۰۰ |
| بیشینهٔ اندازهٔ بدنهٔ درخواست | ۲۵۶ KB |
| نرخ دریافت | ۶۰ درخواست/دقیقه به‌ازای کلید/کاربر (پیش‌فرض) |

تخطی از اندازه → `413`؛ تخطی از نرخ → `429` + `Retry-After`.

## فرمت ISO 8601 UTC

- قالب: `YYYY-MM-DDTHH:MM:SS(.mmm)?Z` — مقدماتیِ میلی‌ثانیه اختیاری؛ **فقط UTC**؛
  offset (مثل `+03:30`) مجاز نیست.
- نمونهٔ معتبر: `2026-01-15T10:30:00.000Z`
- نمونهٔ نامعتبر: `2026-01-15T10:30:00+03:30` (offset)، `2026-01-15 10:30:00Z`
  (فاصله به‌جای T).
- اعتبارسنجی تقویمی انجام می‌شود (سال کبیسه، بازهٔ روز/ماه/ساعت). پارسر C++ بازهٔ
  نمای‌پذیرِ `time_point` با دقت نانوثانیه را هم چک می‌کند: سال‌های 1678..2261 مجاز
  و بیرونِ آن با `InvalidTimestamp` رد می‌شود (تا رفتن به رفتار تعریف‌نشدهٔ سرریز علامت
  نداشته باشیم).

## مثال JSON

```json
{
  "event_id": "0d5b2b6e-6bd6-4c78-9e34-a1b2c3d4e5f6",
  "schema_version": 1,
  "event_time": "2026-01-15T10:30:00.000Z",
  "source_id": "prod-web-02",
  "source_type": "infra",
  "severity": "high",
  "category": "auth",
  "message": "Failed login for user_admin",
  "attributes": { "action": "login_failed" },
  "correlation_id": "sess-8f3a",
  "trace_id": "trc-77c1",
  "actor": "user_admin"
}
```

همین رخداد بعد از پردازش، `ingest_time`، `status` و `origin` سروری می‌گیرد و در
[API_FA.md](API_FA.md) و [DETECTION_RULES_FA.md](DETECTION_RULES_FA.md) دیده می‌شود که
کدام قانون روی آن شعله می‌زند.
